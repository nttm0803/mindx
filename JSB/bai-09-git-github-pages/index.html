🚀 Bài 9: Git, GitHub và đưa website lên mạng

Đến giờ website của em mới chỉ chạy trên máy của em (Live Server, địa chỉ 127.0.0.1). Bạn bè, bố mẹ, thầy cô không mở được. Bài này em sẽ học cách lưu code bằng Git, đưa code lên GitHub và deploy (xuất bản) website để ai cũng mở được bằng một đường link, hoàn toàn miễn phí.

1. Git và GitHub là gì?

1.1. Vấn đề khi chưa có Git

Em đã bao giờ có một thư mục như thế này chưa?

📁 du-an-cuoi-khoa 📄 index.html 📄 index-ban-cu.html 📄 index-sua-lan-2.html 📄 index-FINAL.html 📄 index-FINAL-that-su.html 😵

Lưu nhiều bản như vậy rất rối, và nếu máy hỏng thì mất hết. Git sinh ra để giải quyết chuyện này.

1.2. Định nghĩa

🗂 Git

  • Là phần mềm cài trên máy tính.
  • Giúp lưu lại lịch sử thay đổi của code: mỗi lần lưu gọi là một commit.
  • Có thể quay lại bất kỳ phiên bản nào trước đó.
  • Chạy được cả khi không có Internet.

🐙 GitHub

  • Là trang web (github.com) lưu code trên mạng.
  • Giống Google Drive dành cho code.
  • Mỗi dự án trên GitHub là một repository (gọi tắt là repo).
  • Có tính năng GitHub Pages: biến repo thành website miễn phí.

🧠 Dễ hiểu: Git giống cuốn album ảnh em giữ ở nhà – mỗi commit là một tấm ảnh chụp lại dự án ở thời điểm đó. GitHub giống trang mạng xã hội nơi em đăng album lên để cất giữ an toàn và chia sẻ cho người khác xem.

1.3. Code đi qua 4 "ngăn"

📁 Thư mục làm việc Nơi em sửa code bằng VS Code
→git add
📦 Khu chuẩn bị (staging) Chọn file sẽ được lưu
→git commit
📚 Kho trên máy (local repo) Lịch sử các commit

☁ GitHub (remote repo) Kho trên mạng

🧠 Dễ hiểu – gửi bưu phẩm: git add = bỏ đồ vào hộp. git commit = dán kín hộp và ghi nhãn "trong hộp có gì". git push = mang hộp ra bưu điện gửi đi.

1.4. Deploy là gì?

Deploy (triển khai / xuất bản) là đưa website từ máy của em lên một máy chủ trên Internet, để có một đường link mà ai cũng mở được. Trong bài này, máy chủ đó chính là GitHub Pages.

2. Chuẩn bị (chỉ làm 1 lần)

2.1. Tạo tài khoản GitHub

1 Vào github.com/signup, nhập email, mật khẩu và username.
2 Mở email để xác nhận tài khoản (nhập mã GitHub gửi về).
💡 Username rất quan trọng vì nó nằm trong link website của em: https://username.github.io/...
Nên chọn tên ngắn, viết thường, không dấu, ví dụ nguyenvanan, an-nguyen-2011. Tránh tên kiểu xXxSieuNhanxXx – sau này em sẽ dùng GitHub để nộp hồ sơ đấy!

2.2. Cài Git

1 Vào git-scm.com/downloads → chọn Windows → tải bản 64-bit Git for Windows Setup.
2 Mở file vừa tải, bấm Next liên tục (giữ cài đặt mặc định) → Install.
3 Tắt hẳn VS Code rồi mở lại để VS Code nhận ra Git.
4 Trong VS Code, mở Terminal bằng Ctrl + ` (phím dưới phím Esc), gõ lệnh sau để kiểm tra:
git --version
# Kết quả đúng: git version 2.xx.x.windows.x
💡 Máy Mac: mở Terminal, gõ git --version. Nếu chưa có, máy sẽ tự hỏi cài đặt – bấm Install.

2.3. Khai báo tên và email cho Git

Mỗi commit sẽ ghi lại ai là người lưu. Em khai báo một lần duy nhất (thay bằng thông tin của em, dùng email đã đăng ký GitHub):

git config --global user.name "Nguyen Van An"
git config --global user.email "an@example.com"

# Kiểm tra lại:
git config --global --list

3. Các lệnh Git cơ bản

3.1. Mở đúng thư mục dự án

Trong VS Code chọn File → Open Folder → chọn thư mục dự án (ví dụ tiem-banh-may). Mở Terminal (Ctrl + `), Terminal sẽ tự đứng ở đúng thư mục đó.

⚠ Mở đúng thư mục chứa index.html của dự án, không mở thư mục cha (như Desktop hay Documents). Nếu không, Git sẽ "theo dõi" cả trăm file không liên quan!

3.2. Bảng lệnh

3.3. Thực hành: commit đầu tiên

git log --oneline
# a1b2c3d Tao trang chu tiem banh

❌ Chưa tốt

  • "sua"
  • "abc"
  • "update"

→ Một tuần sau em sẽ không nhớ mình đã sửa gì.

✅ Tốt

  • "Them trang dat banh"
  • "Sua menu bi lech tren dien thoai"
  • "Doi mau nut thanh mau hong"

→ Đọc là biết ngay commit đó làm gì.

3.5. Cách 2: Dùng nút bấm trong VS Code (không cần gõ lệnh)

VS Code có sẵn công cụ Source Control (biểu tượng 3 chấm nối nhau ở thanh bên trái, hoặc Ctrl + Shift + G):

Gõ lệnhBấm nút trong Source Control

git add .Rê chuột vào dòng Changes → bấm dấu +
git commit -m "..."Gõ lời nhắn vào ô Message → bấm ✓ Commit
git pushBấm Sync Changes (hoặc Publish Branch ở lần đầu)

💡 Nên học gõ lệnh trước để hiểu bản chất, sau đó dùng nút bấm cho nhanh. Hai cách cho kết quả giống hệt nhau. Chữ cái cạnh tên file trong VS Code: U = Untracked (file mới), M = Modified (đã sửa), A = Added (đã add).

4. Đẩy code lên GitHub

4.1. Tạo repository (repo) trống trên GitHub

Ở phần 3, em đã có kho Git trên máy (local repo). Bây giờ em cần tạo thêm một kho trên mạng (remote repo) trên GitHub để chứa code đó. Repo trên GitHub phải được tạo trước, rồi mới nối máy với nó được.

🧠 Dễ hiểu: Muốn gửi bưu phẩm thì người nhận phải có địa chỉ nhà trước. Tạo repo trên GitHub chính là "xây nhà" và lấy địa chỉ (đường link repo) để lát nữa gửi code tới.

Bước A – Mở trang tạo repo mới

1 Vào github.com và đăng nhập (Sign in) bằng tài khoản đã tạo ở mục 2.1.
2 Chọn một trong 3 cách (kết quả như nhau):
  • Bấm dấu + ở góc trên bên phải (cạnh ảnh đại diện) → chọn New repository.
  • Hoặc ở trang chủ (Dashboard), cột bên trái, bấm nút xanh lá New (cạnh chữ Top repositories).
  • Hoặc gõ thẳng địa chỉ github.com/new – nhanh nhất!
3 Trang "Create a new repository" hiện ra như Hình 2. Các số đỏ 1 → 5 là những chỗ em cần điền, giải thích ở Bước B.

💡 GitHub thỉnh thoảng đổi giao diện. Ở giao diện cũ, Public / Private là 2 nút tròn ◉ ○ và README là ô tích ☐ "Add a README file". Vị trí các ô có thể khác một chút, em chỉ cần tìm đúng tên các mục.

Bước B – Điền thông tin từng ô

4 (1) Owner: để nguyên là username của em. Repository name: gõ tên repo – tên này sẽ nằm trong link website, nên đặt viết thường, không dấu, không khoảng trắng, nối bằng gạch ngang.
✅ Tên tốt❌ Tên nên tránhVì sao tránh?
tiem-banh-mayTiệm Bánh MâyCó dấu, khoảng trắng → GitHub tự đổi thành Ti-m-B-nh-M-y rất xấu
du-an-cuoi-khoaDuAnCuoiKhoa_FINAL2Lẫn chữ hoa, khó nhớ, dễ gõ sai link
shop-teenabc, testĐọc tên không biết dự án làm gì

Gõ xong, GitHub kiểm tra ngay: thấy dòng ✅ ... is available là dùng được. Nếu báo The repository ... already exists on this account nghĩa là em đã có repo trùng tên → đặt tên khác.

5 (2) Description (không bắt buộc): một câu ngắn mô tả dự án, ví dụ "Website tiệm bánh – dự án cuối khóa MindX". Có thể bỏ trống.
6 (3) Visibility: chọn Public.
  • Public = công khai, ai cũng xem được code. Bắt buộc để dùng GitHub Pages miễn phí.
  • Private = riêng tư, chỉ em xem được → tài khoản miễn phí không bật được GitHub Pages.
7 (4) Add README / .gitignore / license: để trống hết (README = Off, .gitignore = No .gitignore, license = No license).
⚠ Vì sao KHÔNG tạo README? Code của em đã có sẵn trên máy và đã commit. Nếu tạo thêm README trên GitHub, repo trên mạng sẽ có 1 commit mà máy em không có → lúc push sẽ bị lỗi ! [rejected] ... (fetch first) (xem phần 7). Repo phải trống hoàn toàn thì mới push lần đầu dễ dàng.
8 (5) Kiểm tra lại một lượt rồi bấm nút xanh lá Create repository.

Bước C – Đọc trang "Quick setup" và lấy link repo

9 Tạo xong, GitHub chuyển sang trang của repo (đang trống) với khung Quick setup như Hình 3. Trang có nhiều khối, em chỉ cần quan tâm mấy chỗ được đánh dấu:
  • A HTTPS: đảm bảo đang chọn HTTPS (không chọn SSH). Link luôn có dạng https://github.com/username/ten-repo.git.
  • B Bấm biểu tượng 📋 để copy link, lát nữa dán vào lệnh git remote add origin.
  • ✅ "…or push an existing repository from the command line": đúng tình huống của em – đã có code và commit trên máy. 3 lệnh trong khối này chính là 3 lệnh ở mục 4.2 bên dưới.
  • ❌ "…or create a new repository on the command line": dành cho người chưa có code → bỏ qua, vì em đã git init và commit ở phần 3 rồi.
💡 Đừng đóng tab này! Giữ trang Quick setup mở để copy lệnh. Lỡ đóng rồi? Vào github.com/username/ten-repo – khi repo còn trống, trang Quick setup sẽ hiện lại.
10 Kiểm tra nhanh trước khi sang 4.2:
  • Repo tên đúng, viết thường, không dấu
  • Có nhãn Public cạnh tên repo
  • Repo trống (đang hiện trang Quick setup, chưa có file README)
  • Đã copy link HTTPS kết thúc bằng .git

⭐ NGOÀI BÀI HỌC – Lỡ chọn sai? Vào tab ⚙ Settings của repo: đổi tên ở ô Repository name → Rename; đổi Private ↔ Public ở cuối trang, mục Danger Zone → Change visibility. Nếu lỡ tạo README, cách dễ nhất là xóa repo (cũng ở Danger Zone → Delete this repository) rồi tạo lại repo trống.

4.2. Nối máy với GitHub và push

Quay lại Terminal trong VS Code (đang đứng ở thư mục dự án), gõ 3 lệnh – thay link bằng link repo đã copy ở bước 9. Thứ tự 2 lệnh đầu có thể khác trang Quick setup một chút, kết quả vẫn giống nhau:

git branch -M main
# Đổi tên nhánh chính thành "main" (tên chuẩn hiện nay trên GitHub)

git remote add origin https://github.com/username/tiem-banh-may.git
# "origin" là biệt danh của repo trên GitHub, để lần sau khỏi gõ cả link dài

git push -u origin main
# Đẩy nhánh main lên origin. "-u" để những lần sau chỉ cần gõ: git push
💡 Lần push đầu tiên, Windows sẽ hiện cửa sổ "Sign in to GitHub" → bấm Sign in with your browser → trình duyệt mở ra → bấm Authorize. Máy sẽ nhớ tài khoản, các lần sau không phải đăng nhập lại.

Push xong, em tải lại trang repo trên GitHub (F5): trang Quick setup biến mất, thay bằng danh sách file như Hình 4. 🎉

💡 So sánh với thư mục trên máy: các file phải giống hệt, và index.html phải nằm ngay ngoài cùng danh sách (không nằm trong thư mục con) – đây là điều kiện để deploy ở phần 5.

5. Deploy website bằng GitHub Pages

5.1. Bật GitHub Pages

1 Trong trang repo, bấm tab ⚙ Settings (thanh ngang phía trên).
2 Cột bên trái, mục Code and automation → bấm Pages.
3 Phần Build and deployment → Source: chọn Deploy from a branch.
4 Phần Branch: chọn main, thư mục / (root) → bấm Save.
5 Chờ khoảng 1–2 phút, tải lại trang Settings → Pages. Dòng chữ "Your site is live at ..." hiện ra kèm đường link. Bấm Visit site! 🚀
Your site is live at https://username.github.io/tiem-banh-may/ ↑ tên tài khoản ↑ tên repo

💡 Muốn xem quá trình deploy đang chạy tới đâu? Vào tab Actions của repo: 🟡 vàng = đang deploy, ✅ xanh = xong, ❌ đỏ = lỗi.

5.2. Quy tắc để website chạy đúng trên GitHub Pages

Quy tắcVì sao?
Trang chủ phải tên là index.html và nằm ngay ngoài cùng repo (không nằm trong thư mục con) GitHub Pages tự tìm index.html ở thư mục gốc. Không có → lỗi 404.
Dùng đường dẫn tương đối: images/logo.png, style.css Đường dẫn kiểu C:\Users\An\Desktop\logo.png chỉ có trên máy em, lên mạng sẽ mất ảnh.
Viết đúng chữ hoa / chữ thường của tên file Windows coi Logo.PNG và logo.png là một, nhưng máy chủ GitHub coi là 2 file khác nhau.
Tên file, thư mục không dấu, không khoảng trắng: banh-kem.png thay vì Bánh Kem.png Dấu và khoảng trắng trong link dễ gây lỗi không tìm thấy file.

Cấu trúc thư mục đúng:

📁 tiem-banh-may ← thư mục được git init, cũng là repo 📄 index.html ← trang chủ, nằm ngoài cùng ✅ 📄 products.html 📄 style.css 📁 images 🖼 hero.svg
⚠ Không đưa lên GitHub mật khẩu, số điện thoại, địa chỉ nhà hay thông tin riêng tư. Repo Public thì ai cũng xem được toàn bộ code của em.

5.3. ⭐ NGOÀI BÀI HỌC: Cách nhanh không cần cài Git

Nếu máy ở phòng học chưa cài được Git, em vẫn có thể deploy bằng cách kéo thả:

1 Tạo repo mới như mục 4.1 → ở trang repo trống, bấm link uploading an existing file.
2 Mở thư mục dự án trên máy, chọn tất cả file và thư mục bên trong (Ctrl + A), kéo thả vào trang GitHub.
3 Bấm Commit changes, sau đó bật GitHub Pages như mục 5.1.

💡 Kéo các file bên trong, không kéo cả thư mục ngoài cùng – nếu không index.html sẽ nằm trong thư mục con và web báo 404. Cách này tiện nhưng mỗi lần sửa lại phải upload thủ công, không có lịch sử rõ ràng như dùng Git.

6. Sửa website và cập nhật lên mạng

Từ giờ, mỗi lần sửa code em chỉ cần lặp lại vòng 3 lệnh:

git add .
git commit -m "Them mau hong cho nut dat banh"
git push

Đợi khoảng 1 phút rồi tải lại website (nhấn Ctrl + F5 để trình duyệt bỏ bản cũ đã lưu) – thay đổi đã lên mạng!

🔁 Thói quen tốt: Làm xong một phần nhỏ (một section, một trang, sửa một lỗi) là commit ngay. Cuối buổi học thì push. Như vậy về nhà em vẫn tiếp tục được, và nếu lỡ làm hỏng thì vẫn quay lại được bản trước.

6.1. ⭐ NGOÀI BÀI HỌC: Tiếp tục làm ở máy khác

Ở nhà muốn lấy code từ GitHub về máy (lần đầu):

git clone https://github.com/username/tiem-banh-may.git
# Tải toàn bộ repo về thành thư mục tiem-banh-may

Những lần sau, trước khi bắt đầu code, lấy bản mới nhất về:

git pull

✍ Thực hành: Deploy dự án cuối khóa

  1. Mở thư mục dự án cuối khóa của em bằng VS Code.
  2. git init → git add . → git commit -m "Phien ban dau tien".
  3. Tạo repo Public, trống (không README) trên GitHub theo mục 4.1, copy link HTTPS.
  4. git branch -M main → git remote add origin ... → git push -u origin main.
  5. Bật GitHub Pages, mở link website trên điện thoại để kiểm tra responsive.
  6. Sửa một chi tiết nhỏ (ví dụ đổi màu tiêu đề), commit và push lại, kiểm tra website đã đổi chưa.
  7. Gửi link https://...github.io/... cho thầy cô và dán link vào slide thuyết trình.

6.2. Checklist trước khi nộp link

  • Mở link trên trình duyệt ẩn danh (Ctrl + Shift + N) – trang chủ hiện đúng
  • Tất cả ảnh đều hiện (không có ô ảnh vỡ)
  • Bấm hết các link trên menu – không trang nào báo 404
  • Mở trên điện thoại – giao diện không bị vỡ
  • Tiêu đề tab (<title>) đã đổi thành tên dự án
  • Không có thông tin cá nhân nhạy cảm trong code

8. Ôn tập

Bấm vào từng câu để xem đáp án.

1. Git và GitHub khác nhau thế nào?

Git là phần mềm cài trên máy để lưu lịch sử thay đổi code. GitHub là trang web lưu trữ repo Git trên mạng và chia sẻ cho người khác.

2. Sắp xếp đúng thứ tự: git push, git add ., git commit -m "..."

git add . → git commit -m "..." → git push

3. Lệnh nào chỉ cần chạy 1 lần cho mỗi dự án?

git init, git remote add origin ... (và git config chỉ 1 lần cho mỗi máy tính).

4. Lệnh nào dùng để xem file nào đã thay đổi?

git status

5. Username là "minhanh", repo tên "shop-teen". Link GitHub Pages là gì?

https://minhanh.github.io/shop-teen/

6. Trên máy web hiện ảnh đầy đủ, lên GitHub Pages thì mất ảnh Banner.PNG, trong code viết <img src="images/banner.png">. Vì sao?

Máy chủ GitHub phân biệt chữ hoa/thường: Banner.PNG khác banner.png. Cần đổi tên file hoặc sửa src cho khớp.

7. Vì sao repo phải để Public khi dùng GitHub Pages miễn phí?

Tài khoản GitHub miễn phí chỉ bật được GitHub Pages cho repo Public. Vì thế cũng không được để thông tin riêng tư trong code.

8. Khi tạo repo trên GitHub để đẩy code có sẵn trên máy, vì sao không nên tích "Add README"?

Vì README tạo ra một commit trên GitHub mà máy chưa có, lần push đầu sẽ bị từ chối (rejected ... fetch first). Repo cần trống hoàn toàn.

9. Sửa code xong, cần làm gì để website trên mạng cập nhật?

Lưu file → git add . → git commit -m "..." → git push → đợi 1–2 phút rồi tải lại trang.
